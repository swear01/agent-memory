---
title: 自動玩遊戲的操作與通關偏好
scope: global gameplay automation
status: active
updated: 2026-11-27
---

使用者要求這些規則適用於日後所有交給 agent 自動玩的遊戲。

- 從啟動、遊玩到結算都使用 CLI 或只作用在遊戲程序內的控制介面。用啟動命令開 Steam 遊戲，從原生狀態、結算回條和存檔驗證。視窗焦點、桌面游標、滑鼠按鍵和鍵盤由使用者掌控，禁止切換前景或以桌面鍵鼠自動化代替遊戲內控制。
- 保留原生遊戲視窗，使用者想看時可自己切回，即時看到 agent 正在操作的同一局。實測遊戲在失焦背景時仍能接收 CLI 指令並推進。常駐 CLI 可在同一個遊戲程序換關或重試。背景求解可以輔助決策，實際進度須在可觀看的主局執行。
- 使用者允許修改單機遊戲，加入 CLI、遊戲內控制或狀態讀取，以便 agent 自動玩。套用前先備份原檔與存檔，記錄對應遊戲版本和還原方式。沿用使用者原本的存檔，透過遊戲自己的流程保存進度。
- 靠遊戲內可取得的資源、升級、配置與策略通關。保持原生移動、碰撞、資源成本、解鎖條件和結局流程。禁止改傷害或射程、跳過波次或直接寫入通關結果。
- 卡關時看波次、首領路線、資源與升級成本，依證據比較並切換不同的升級路線、塔位和搭配。先用已有資源做有針對性的嘗試；關鍵升級缺代幣時，回打前面關卡補可取得的計時、特色挑戰或其他原生獎勵，再回主線。
- 遊戲有原生提早開波與獎勵時，只有在當前防守足以承受重疊波次時才提早開波。分派子代理操控關卡時，所有代理共同遵循 CLI、可見 GUI 和原生玩法限制，並劃分控制範圍。
- 背包、有待領款項或升級資源能跨回合累積時，用腳本連跑多趟，背包滿或批次結束再集中銷售、領款、兌換和升級。升級前先核對原生存檔裡可用的餘額，確定待領款項已發完。
- 依當次要求設定速度。使用者指定 OpenSpeedy 時，核對它實際作用於可見遊戲的 PID，再用同一段原生遊玩流程的產出與牆鐘時間驗證效果。常駐控制介面負責執行，路線、決策與重試保留在可即時更新的批次腳本，優先在同一局迭代。從啟動到原生結果寫進存檔都按[端到端時間](end-to-end-speed.md)計算，以 [Outhold](../../projects/outhold/native-cli-achievements.md) 與 [Click Mage](../../projects/click-mage/unity-mono-control.md) 為例。
