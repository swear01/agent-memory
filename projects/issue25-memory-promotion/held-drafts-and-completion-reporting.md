# Issue25 完成回報必須對齊草稿終態

控制者最初在 G13–G16 通過且已發布筆記完成 QMD 回讀後，用「全部完成」和「已結案」概括狀態。使用者追問 462 份暫留草稿，才補充它們尚未全部修整解決。關卡採用的是允許明確保留未解紀錄的處置政策；通過這種關卡不能推導每份候選教訓都已完成來源修正或發布。

回報必須同時列出已發布與已驗證成果、未解草稿數量、控制者查核程度及是否仍有工作執行。當時帳冊的 462 份分為 385 份讀過草稿但仍需修整、拆分或進一步來源核對，34 份有具體待修正問題，43 份已核對所選來源仍不足以支持完整結論。這是當次快照，不是固定配額；其中可能仍有值得保留的教訓，不能全部說成無價值或已解決。

當時正確說法應是「本輪已確認筆記的發布與驗證完成，仍有具體未解草稿保留」，而不是省略未解部分後說目標全部完成。保留原始來源與帳冊不等於已提取其中所有有價值資訊；粗略抽查、沒有運行中的 worker 或軟體驗證通過，都不能證明完整召回或內容保留比例。來源不足、混合獨立事件及尚待修正須分別交代，不能用不宣稱完整召回一句話掩蓋已知待辦。

## 後續定案與可重用規則

2026-09-16 使用者要求重新斟酌並清理後，462 份都有明確終態：57 份重寫成 55 篇來源支持筆記，193 份對應已保存的主要教訓，212 份明確排除，不再放入待查佇列。PR81 已合併 main，55 篇全部通過 lexical、hybrid 與全文 QMD 回讀。排除不等於原始歷史為假，也不要求把沒有證據的主張勉強寫成通用規則。

定案必須核對完整原始 ID 集合，逐份留下採用範圍、排除理由及 canonical 對應；不能把整包來源因其中一個教訓獲採用就標為完全驗證。正式發布、QMD 回讀與明確取捨完成後，同步更新現行完成報告，將舊 held 計數保留為有日期的歷史快照，避免下一個控制者把舊狀態當待辦重跑。完整結束的是這次約定的處理流程，不是對所有對話資訊作百分之百召回保證。
