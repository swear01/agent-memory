# NTU DVLab Discord 伺服器架構、身份組分流與頻道治理規範

## 伺服器概述

- 目標伺服器：`NTU DVLab`（Guild ID：`1155808217872466041`）
- 治理核心原則：
  1. **學術與休閒分流**：保留畢業校友與在學生共同閒聊、休閒遊戲的互動空間，同時對未公開研究課題、GPU 算力與機密討論實施權限隔離。
  2. **Opt-in 視線隔離（防洗版）**：非核心頻道（如 Minecraft、Brawl、特定研究領域）採自選領取制；未加入該身分組的成員側邊欄預設隱藏，避免訊息洗版。
  3. **零維護與原生託管**：捨棄需要持續常駐運行的本機/伺服器 Bot 互動按鈕方案，全面改採 Discord 官方原生「社群引導（Community Onboarding / Channels & Roles）」系統，由 Discord 官方伺服器提供 24/7 免費雲端狀態託管。

## Discord API 自動化操作實務守則

1. **身分組層級約束（Role Hierarchy）**：
   - 管理機器人最高身分組必須置於欲指派或修改的身分組之上。
   - 機器人建立的新身分組預設位置在自身下方，可直接指派給包括伺服器擁有者（Owner）在內的成員。
2. **批次更新成員身分組之 Rate Limit（HTTP 429）**：
   - Discord API 對單一 Guild 的成員身分組修改限制極為嚴格（約每 10 次連續請求觸發一次 429）。
   - 批次批次調整成員身分組時，每筆請求之間應保留 `1.0 ~ 1.2 秒` 間隔，或動態解析回應標頭的 `Retry-After` 進行休眠等待。
3. **無成員特權 Intent 下的成員枚舉**：
   - 若 Bot 未在 Developer Portal 開啟 `Server Members Intent`，呼叫 `GET /guilds/{id}/members` 會回傳 `403 Forbidden`。
   - 替代策略：呼叫 `GET /guilds/{id}/members/search?query={q}`（以 a-z、0-9 與特定已知名稱/暱稱分段搜尋），可完整枚舉伺服器現有成員。
4. **歷史訊息與頻道維護最佳實踐**：
   - 凡涉及舊頻道升級（如 `#eda` 轉型為 `#aieda`、`#r11` 移至屆次分區），切勿刪除重開；應採用 `PATCH /channels/{id}` 更新 `parent_id` 與頻道名稱，可無損保留全部歷史討論與附加檔案。
